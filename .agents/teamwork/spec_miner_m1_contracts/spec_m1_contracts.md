### 2.2 Verbatim File Template & Export Syntax

### 2.3 Sourcing & Environment Propagation Semantics

1. **Bash / Zsh Script Ingestion:**
   Scripts SHOULD source `lab.env` using:
   ```bash
   # Source lab environment with path canonicalization
   REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
   if [[ ! -f "$REPO_ROOT/lab.env" ]]; then
       echo "FATAL: $REPO_ROOT/lab.env not found. Phase 1 provisioning required." >&2
       exit 1
   fi
   # shellcheck source=/dev/null
   source "$REPO_ROOT/lab.env"
   ```
2. **Subshell Inheritance:**
   Because each assignment begins with `export`, any command executed in subshells or child processes (e.g. `python3`, `curl`, `aws`, `ssh`) automatically inherits the 15 parameters without requiring `set -a` or manual export loops.
3. **Tilde (`~`) vs `$HOME` Path Handling (Critical Edge Case):**
   In POSIX shells, tilde expansion does NOT occur inside double quotes (e.g. `"~/.ssh/..."` remains literal `~`). If quoted, `ssh -i "$KEY_PATH"` will fail looking for a directory named `~` in the current working directory. Therefore:
   - In `lab.env`, `KEY_PATH` MUST use `$HOME/.ssh/tcp-flood-lab.pem` or the expanded absolute path `/Users/raja/.ssh/tcp-flood-lab.pem`.
4. **Python Sourcing Compatibility:**
   Python scripts can read `lab.env` either via `os.environ` (if sourced prior to invocation) or directly parse the file using this standardized standard-library parser:
   ```python
   import re, os

   def load_lab_env(filepath="lab.env"):
       pattern = re.compile(r'^(?:export\s+)?([A-Za-z_][A-Za-z0-9_]*)=["\']?(.*?)["\']?$')
       env_vars = {}
       with open(filepath, "r", encoding="utf-8") as f:
           for line in f:
               line = line.strip()
               if not line or line.startswith("#"):
                   continue
               match = pattern.match(line)
               if match:
                   k, v = match.groups()
                   v = os.path.expandvars(os.path.expanduser(v))
                   env_vars[k] = v
                   os.environ[k] = v
       return env_vars
   ```

### 2.4 Automated Validation Script (`validate_lab_env.sh`)

Any agent or harness verifying `lab.env` MUST execute the following acceptance check:

```bash
#!/usr/bin/env bash
set -euo pipefail

ENV_FILE="${1:-lab.env}"
if [[ ! -f "$ENV_FILE" ]]; then
    echo "FAIL: Environment file $ENV_FILE does not exist." >&2
    exit 1
fi

# Source target file
# shellcheck source=/dev/null
source "$ENV_FILE"

REQUIRED_VARS=(
    "AWS_REGION" "VPC_ID" "SG_ID" "KEY_NAME" "KEY_PATH"
    "VICTIM_ID" "ATTACKER_ID" "CLIENT_ID"
    "VICTIM_PUB" "ATTACKER_PUB" "CLIENT_PUB"
    "VICTIM_PRIVATE_IP" "ATTACKER_PRIVATE_IP" "CLIENT_PRIVATE_IP"
    "VICTIM_IFACE"
)

ERRORS=0
for var in "${REQUIRED_VARS[@]}"; do
    if [[ -z "${!var:-}" ]]; then
        echo "FAIL: Required variable '$var' is unset or empty in $ENV_FILE" >&2
        ERRORS=$((ERRORS + 1))
    fi
done

# Check key path exists
RESOLVED_KEY=$(eval echo "$KEY_PATH")
if [[ ! -f "$RESOLVED_KEY" ]]; then
    echo "FAIL: KEY_PATH '$RESOLVED_KEY' does not point to an existing file." >&2
    ERRORS=$((ERRORS + 1))
fi

if [[ $ERRORS -gt 0 ]]; then
    echo "Validation failed with $ERRORS errors." >&2
    exit 1
fi

echo "PASS: lab.env is complete and syntactically valid."
```
